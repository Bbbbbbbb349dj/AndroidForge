# Nuvio Enhanced 1.21 (210)

## Changes and bug fixes

- Remove the watched-eye overlay from poster artwork. Watched history, category assignments and explicit mark-watched actions are preserved.
- Remove the Movie/Series dropdown and its container spacing from text-search results, without a replacement control. Discover browsing retains its catalog controls when the query is empty.
- Stop filtering search results by Discover's selected content type. Search includes all enabled, installed catalogs that declare search support, including `popular.movies`, series and custom types. Legacy `extraSupported`/`extraRequired` manifests are recognized. Catalogs requiring a genre are searched across their declared genre options; unsupported mandatory parameters cannot be invented.
- Retain the independent opt-in CloudStream search switch.
- Add a discoverable More like this player action, available throughout movie playback; retain end-of-movie recommendation cards. Fall back to TMDB when the selected tracking recommendation provider has no results. Show an explanatory empty state when no unwatched results are available.
- Connect the player header Back action to Mini Player when enabled, matching system Back. Remove the unrelated hidden-PiP preference gate from the minimize action. Dismiss hosted minimized playback when the setting is disabled. External-player sessions remain managed by the external application.
- Add a visible Night Mode audio-compression action in both player layouts. Connect ExoPlayer to Android 9+ DynamicsProcessing, manage audio-session changes and release the effect. Retain the existing MPV compression filter. Unsupported engines/devices show a disabled control; vendor audio-effect support varies.
- Expose Glass Backgrounds on Controls on the main Playback settings page. Use the existing persisted preference; stop control-backdrop video-frame capture when disabled.
- Remove the Buy Me a Coffee Settings card, implementation and configuration.
- Bundle complete 1.21 release notes so About → What's New works offline and before the GitHub release is published. Load additional history from this fork instead of the unavailable upstream; recognize this fork's release tags and two-part versions.
- Start HLS playback without waiting for quality inspection. Inspect quality variants in the background with a five-second bound, preserve coroutine cancellation and do not reload the running master playlist when inspection finishes.
- Reduce default initial buffering to one second for network sources and 250 ms for local files, while retaining custom user buffer settings and separate rebuffer thresholds. This is a latency trade-off, not a guarantee against provider/network stalls.
- Fetch four HLS download segments concurrently and write/decrypt them in playlist order. Independently cancel each in-flight segment on pause/cancellation. Validate byte-range responses, bound each segment to 32 MiB, and sync video data before writing a batch checkpoint. Progressive-file download behavior remains unchanged.
- Keep Fetch / refresh subtitles accessible when embedded or local sidecar subtitles already exist. Add All, SDH/CC, Forced and SRT track filters; preserve provider flags and release labels.
- Save a selected remote subtitle beside a downloaded/local video once. Preserve existing sidecars and reuse the saved track without contacting the subtitle provider on subsequent playback.
- Replace the personal profile hero with a responsive watching dashboard: avatar/greeting, profile edit/switch, collection cards, seven-day activity summary, watch-time and taste analysis, loading/refresh and empty states. All counts come from the active profile's existing repositories, not invented statistics. Collection cards open the real title lists, including informative empty collections.
- Retain the verified v1.20 baseline: Downloads navigation, Unlimited download setting, rating-map position/reordering, CloudStream compatibility, subtitle sync, local-media playback, category persistence and prior playback-recovery improvements.

## Validation and limits

Added Kotlin common tests for search capabilities/legacy manifests, subtitle filters, release-tag handling and bundled notes; Android host tests cover HLS concurrency/ranges/cancellation/size limits and one-time offline subtitle saving. The release workflow must run the tests before publishing its APK. Run the focused suite with `./gradlew -Pnuvio.android.distribution=full -Pnuvio.testSuite=v121 :composeApp:testAndroidHostTest`. Without the test-suite property, all inherited tests remain available; some legacy server tests in the pinned archive currently reference APIs absent from that archive and fail compilation. The release gate is explicitly scoped rather than silently deleting those tests.

SDH/forced subtitles are supplied by installed subtitle add-ons; this release cannot synthesize missing translations, SDH descriptions or forced tracks. Initial subtitle retrieval requires a network connection and recognizable title/episode metadata. Unidentified files cannot be reliably matched by filename alone. Playback startup, sustained buffering and download throughput require device/provider testing; no universal speed claim is made.

The build recipe starts with the same pinned base source and v1.20 patch pipeline as workflow run `45692499534` (helper commit `5b52a98917dbe51d8a995a10d5f3a778b0353ecb`), then applies the strict, reviewable v1.21 patch. The working tree also contains the materialized app source for direct review.

## Upgrade safety

The release workflow verifies that the new APK has exactly the same public signing-certificate fingerprints as the v1.20 APK before uploading or publishing it. The older private key is cached on another branch, and Actions caches are branch-scoped. If the original key is not available through the repository's existing `NUVIO_RELEASE_*` Actions secrets, publication stops rather than silently publishing an incompatible update. Private signing material must remain in secure Actions secrets/cache, never in source control or chat. Do not uninstall the existing app to work around a signature mismatch.
